🎯 Executive Summary

🚀 Key Finding: Dubai is Already Building This

Dubai Municipality launched "Dubai Live" in October 2025 — an AI-powered digital twin command hub. RTA (Roads and Transport Authority) deployed AI traffic signal control across 620 intersections with V2X connectivity, targeting 100% main road coverage by 2026. This means the infrastructure exists — the opportunity is to build an open-source layer on top of it.

This report provides a complete blueprint for building a network traffic digital twin of Dubai — a real-time virtual replica of the city's traffic network that can simulate congestion, predict bottlenecks, and proactively intervene via signal control, rerouting, and driver advisories.

🗺️ 3D Map Foundation

OpenStreetMap + Cesium OSM Buildings provide free 3D city models. GeoDubai offers official Dubai 3D data. OSM2World converts to glTF/CityGML for simulation engines.

🚦 Real-Time Simulation

SUMO (Simulation of Urban Mobility) with TraCI Python API enables real-time traffic simulation. CityFlow provides 20x faster RL-ready simulation for signal control.

📡 Live Data Integration

HERE Traffic API, RTA GTFS feeds, IoT sensors via MQTT/Kafka. Kalman filters fuse noisy sensor data into clean state estimates for the twin.

🧠 Proactive Intervention

Reinforcement learning (PressLight, CoLight, Traffic-R1) for adaptive signal control. LLM-based reasoning for zero-shot generalization to unseen congestion patterns.

🏗️ System Architecture

The digital twin follows a physical-virtual synchronization pattern: real-world sensors feed into a state estimation layer that keeps the simulation in sync with reality, while the simulation outputs predictions and control signals back to the physical world.

💡 Synchronization Pattern (from V2X Digital Twin Paper)

The key insight from the Madison, Wisconsin deployment (arxiv 2410.00356): use temporal synchronization (align timestamps across data sources), spatial matching (map GPS to road segments), and a feedback loop (twin sends signal timing back to physical world via JSON commands). Edge servers process data within 500ms latency.

🚦 Traffic Simulation Engines

SUMO — Primary Simulation Engine

Why SUMO for Dubai?

SUMO (Simulation of Urban Mobility) is the best fit because: (1) direct OSM import via netconvert, (2) real-time TraCI Python API for live data injection, (3) microscopic simulation models individual vehicles, (4) traffic signal control integration, (5) proven in Dubai-scale deployments.

SUMO Dubai Pipeline Bash
# Download Dubai network from OSM osm_download --region "Dubai, UAE" --output dubai.osm.xml # Convert to SUMO network netconvert --osm-files dubai.osm.xml -o dubai.net.xml # Generate traffic demand randomTrips -n dubai.net.xml -r dubai.rou.xml -e 3600 # Run simulation with TraCI sumo -n dubai.net.xml -r dubai.rou.xml --remote-port 8813
SUMO TraCI — Real-Time Digital Twin Sync Python
import traci from kafka import KafkaConsumer import json # Connect to running SUMO instance traci.start(["sumo", "-c", "dubai.sumocfg"]) # Kafka consumer for real-time traffic data consumer = KafkaConsumer('dubai-traffic') for msg in consumer: traffic_data = json.loads(msg.value) # Inject real-world counts into SUMO induction loops for segment in traffic_data['segments']: loop_id = segment['loop_id'] traci.inductionloop.setVehicleData( loop_id, real_count=segment['vehicle_count'], real_speed=segment['speed'] ) # Advance simulation one step traci.simulationStep() # Read current state for digital twin for veh_id in traci.vehicle.getIDList(): pos = traci.vehicle.getPosition(veh_id) speed = traci.vehicle.getSpeed(veh_id) # Publish to visualization layer... traci.close()

CityFlow — RL-Ready Alternative

When to Use CityFlow

CityFlow is 20x faster than SUMO and purpose-built for multi-agent RL traffic signal control. Use it when training RL agents (PressLight, CoLight, Traffic-R1). It uses a thread-safe C++ engine with Python bindings via pybind11. Tested on Hangzhou with 100+ intersections.

CityFlow — RL Signal Control Loop Python
import cityflow import numpy as np eng = cityflow.Engine(config_file="dubai_4x4.json", thread_num=1) for step in range(3600): # Get state: queue lengths per lane lane_waits = eng.get_lane_waiting_vehicle_count() current_phase = eng.get_traffic_light_state(inter_id) # RL agent selects action action = agent.select_action(lane_waits, current_phase) eng.set_traffic_light(inter_id, action) # Reward: negative total waiting reward = -sum(lane_waits.values()) eng.next_step()

Reinforcement Learning for Signal Control

PressLight (KDD 2019)

Max-pressure control: reward = upstream queue − downstream queue. Theoretically optimal for network-level throughput. Simple, effective baseline.

CoLight (CIKM 2019)

Attention-based coordination between neighboring intersections. Captures spatial dependencies. 15% better than PressLight on large grids.

Traffic-R1 (2025)

LLM-based (Qwen2.5-3B) with RL fine-tuning. Zero-shot generalization to unseen cities. Deployed in Tier-1 Chinese city, 55k+ drivers/day, 5% queue reduction.

LibSignal

Unified library for CityFlow + SUMO RL training. Provides standardized environments, baselines, and evaluation. Best starting point for experiments.
